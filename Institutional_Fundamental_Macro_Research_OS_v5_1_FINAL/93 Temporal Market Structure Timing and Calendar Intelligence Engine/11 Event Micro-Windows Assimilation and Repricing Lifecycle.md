# Event Micro-Windows, Assimilation and Repricing Lifecycle

V15 connects event time to V11 consumption and V12 narrative selection.

## Lifecycle
1. `EXPECTATION_FORMATION` — before release;
2. `SURPRISE_RECOGNITION` — first print/headline;
3. `CAUSAL_CHANNEL_SELECTION` — rates, policy path, earnings, growth, inflation, etc.;
4. `CROSS_ASSET_TRANSMISSION`;
5. `NARRATIVE_COORDINATION`;
6. `POSITIONING/LIQUIDITY_ADJUSTMENT`;
7. `PERSISTENCE_OR_FAILURE`;
8. `CONSUMPTION_OR_REOPENING`.

## Timing output
The engine does not decide that T+5 or T+15 is universally “safe.” It reports whether reliable reaction evidence exists. On exceptionally complex releases, first reaction can remain `UNSTABLE`; on simple binary surprises, the causal leader may stabilize faster.

## Edge interaction
An existing Active Edge can survive an event only if the post-event state is re-adjudicated. An event-expired permission is never silently extended because price happened to continue.

## Learning
Record how long it took for the correct driver/narrative to dominate, whether the first reaction failed, and whether the previous pre-event expiry was too early (`OVER_VETO`) or too late (`UNDER_VETO`).
