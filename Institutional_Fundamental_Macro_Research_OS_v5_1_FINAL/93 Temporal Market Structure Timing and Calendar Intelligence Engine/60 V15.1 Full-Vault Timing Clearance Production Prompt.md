# Alpha Lab V15.1 — Full-Vault Timing Clearance Production Prompt

Run V11/V12/V13 first and create a `CORE_EDGE_CANDIDATE` for each of XAUUSD, NASDAQ100, SP500, DJIA, EURUSD and USDJPY. Do **not** call any state `EDGE_ACTIVE` yet.

Then execute V15.1 independently for each symbol and the shared global clock graph.

## A. Resolve exact temporal identity
Resolve broker/expression/reference market, relevant venues, contract/option series where material, cash/futures/benchmark clocks, IANA timezones, DST, business/settlement calendars and holiday/half-day status.

## B. Retrieve current official clocks
Use current primary sources for scheduled macro/central-bank/Treasury events, cash open/close, WMR/LBMA benchmarks, futures settlement/roll/expiry/final settlement, option expiry/settlement, index rebalance/reconstitution/effective dates, material earnings/corporate clocks and month/quarter/year-end mechanisms. Preserve tentative/TBD/revised status.

## C. Build dependency-aware clock graph
For every material clock record mechanism, source, materiality, independence relation and next transition. Collapse same-root mechanisms; do not count linked clocks multiple times.

## D. Apply no-technical boundary
Do not use indicators, price patterns, support/resistance, ICT, chart momentum or price-only seasonality to clear Timing. Session names and calendar labels have no directional sign.

## E. Event/hazard adjudication
Classify reset severity and construct an adaptive pre-hazard boundary. Fixed T-minus points are review anchors only. A later high-impact event is not a veto by existence.

## F. Time-to-exploit
Compare the safe window with the external M1 Donchian execution profile using forward duration telemetry when mature; otherwise use conservative qualitative safe margin. Donchian supplies duration/execution telemetry only, never direction.

## G. Operational feasibility
Subtract analysis/transport/ingestion latency. Ensure `valid_until` is before the earliest hard hazard and that required review is feasible. If not, expire fail-closed or HOLD/VETO.

## H. Return clearance
Exactly one: `CLEAR`, `CLEAR_WITH_CONSTRAINTS`, `HOLD`, `VETO`, `UNDETERMINED_MATERIAL`, `CLOSED`.

## I. Final Edge handoff
- Only core `ACTIVE_CANDIDATE_BULL/BEAR` + `CLEAR/CLEAR_WITH_CONSTRAINTS` may become `EDGE_ACTIVE`.
- `HOLD` → `EDGE_CONDITIONAL`.
- `VETO` → `EDGE_CONDITIONAL` or `EVENT_OR_FRAGMENTED`, permission NO_TRADE.
- `UNDETERMINED_MATERIAL` → `INSUFFICIENT_EVIDENCE` or Conditional, permission NO_TRADE.
- Timing cannot upgrade BIAS_ONLY/NO_EDGE/EDGE_RELATIVE.

Every Timing-blocked Conditional must include a complete `Why Not Active?` with clock, mechanism, source, hard/soft blocker, time boundary, next clearing transition, upgrade condition, downgrade condition and exact `valid_until` logic.
