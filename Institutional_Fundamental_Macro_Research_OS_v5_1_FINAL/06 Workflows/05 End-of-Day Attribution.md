## Five-Layer Attribution

Evaluate each layer independently:

| Layer | Question | Score |
|---|---|---:|
| State | Was the economic/financial state understood correctly? | 0–2 |
| Expectations | Was the priced baseline identified correctly? | 0–2 |
| Transmission | Did the expected channel operate? | 0–2 |
| Timing | Was the thesis relevant to this session? | 0–2 |
| Execution | Was the technical setup followed? | 0–2 |

Do not allow execution P&L to rewrite earlier observations.

## Outcome Categories

### A. Correct thesis, correct execution
Preserve the process. Do not overgeneralize from one trade.

### B. Correct thesis, poor execution
The macro work had value, but entry, stop, timing, or discipline destroyed it.

### C. Wrong thesis, correct risk process
A normal loss. Improve the model without attacking the risk rules.

### D. Wrong thesis, poor execution
Priority repair: prevent compounding errors.

### E. Thesis irrelevant, flow dominated
Record why the macro horizon did not match the session.

### F. No-trade decision was correct
Count preserved capital and avoided cognitive damage as a valid outcome.

## Causal Postmortem

Write the causal chain as it actually happened:

```text
Information
→ expectation change
→ rate/dollar/risk-premium response
→ cross-asset confirmation or failure
→ index/asset response
→ technical setup
→ trade outcome
```

Then compare it with the pre-market chain.

## Prediction Error Ledger

Track four distinct errors:

1. **State error** — the economy/financial system was misread.
2. **Expectation error** — the market had priced something different.
3. **Transmission error** — the right information produced the wrong assumed asset effect.
4. **Timing error** — the thesis was directionally valid but not relevant during the holding window.

This classification is more useful than “fundamentals did not work.”

## Updating Rules

- One session should rarely change a structural model.
- A repeated transmission failure should reduce confidence quickly.
- A new regime can invalidate historical relationships.
- A single extreme event should not be normalized as the new baseline.
- Update process rules only after identifying whether the error is systematic.
