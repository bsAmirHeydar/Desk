# REV 3.3.6 — Economic Comparison Anchor Integrity

## Problem

A previous acquisition/fetch is not necessarily a previous economic observation.

Two hourly Alpha Desk runs can fetch the same daily, weekly, monthly, or
quarterly source record. Equality across those two fetches proves only that no
new value was ingested between runs. It does **not** prove that the underlying
economic variable had zero change over the reasoning horizon.

Examples:
- Broad Dollar fetched twice while both observations reference `7-AUG-26`.
- 2Y Treasury fetched twice while both reference `2026-08-14`.
- SOFR fetched twice while both reference `2026-08-13`.

These are repeated fetches of one economic state, not two economic states.

## Contract

P03 keeps two distinct clocks:

1. `previous_fetch_observation`
   - prior acquisition/run lineage;
   - useful for no-refire and new-information detection;
   - never interpreted as an economic delta by itself.

2. `previous_economic_observation`
   - most recent earlier observation with a distinct explicit
     `reference_period`, `event_time`, or `published_at`;
   - the only generic prior anchor eligible for economic-delta reasoning.

If no distinct economic anchor exists, the packet emits an explicit status such
as `NO_DISTINCT_ECONOMIC_ANCHOR` or `NO_CURRENT_ECONOMIC_MARKER`.

## Hard rule

Repeated fetch equality must never become `NEUTRAL`, `delta=0`, or a directional
impulse claim unless the underlying economic/event clocks support that claim.

This revision does not add Direction or Permission authority.
