# Statistical Learning Promotion and Multiple-Testing Control — V20 bridge

The original `OBSERVATION → CANDIDATE → VALIDATED → CANONICAL` concept is superseded for D3 modifiers by the more explicit Module 102 lifecycle:

`OBSERVATION → SHADOW → CANDIDATE → VALIDATED → PROMOTED → MONITORED → RETIRED`.

A promotion record must include sample size, independent-root-event count, market/regime coverage, holdout results, effect-direction stability, failure cases, multiple-testing family, retirement condition and independent-validator sign-off.

Discovery rules are never promoted on in-sample performance alone. If many hypotheses are screened, the research record must state the correction/control method or mark the finding exploratory.

No automatic Vault mutation from a single run is permitted. Canonical authority now lives in Module 102 `config/promotion_registry.json`.
