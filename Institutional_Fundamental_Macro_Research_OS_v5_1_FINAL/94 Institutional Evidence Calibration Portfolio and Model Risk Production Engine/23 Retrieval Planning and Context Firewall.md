# Retrieval Planning and Context Firewall

`FULL_VAULT` means **full scientific availability with no omitted material dimension**, not literal ingestion of every note on every run.

## Smallest-sufficient-set rule
Each run builds a Retrieval Plan containing:
1. production authority and materiality doctrine;
2. Fundamental authority;
3. Narrative transmission authority;
4. instrument/asset-family authority;
5. asset-specific operating book;
6. Timing authority/sub-engine;
7. Edge/permission/learning authority;
8. current event/driver modules only when material;
9. operational/evidence contracts.

Additional notes are admitted when they close a named evidence gap or test a rival model.

## Status firewall
Load-bearing production retrieval may use only statuses allowed by `config/retrieval_policy.json`. `supporting-legacy`, `archived`, `archived-superseded`, `deprecated` and equivalent historical objects are forbidden as decision authority. They may be used only in explicit history/audit mode and cannot supply a load-bearing production claim.

The plan must cover all mandatory dimensions but minimize duplicate context. Use `tools/alphalab_retrieval_plan.py` to generate/validate the deterministic core plan and any requested extras.
